# «Черновик» — как работает каждый элемент

Код: `index.html` + `css/01–13` + `js/01–25` (порядок подключения = порядок зависимостей) + `api/*.php`.
Ниже — каждый элемент, где живёт и какой функцией работает.

---

## 1. Каркас и состояния

| Состояние | Как задаётся | Что меняет |
|---|---|---|
| Экран библиотеки | `#library` | Главный экран со списком книг |
| Редактор | `#workspace` + `body` без классов | Сайдбар + текст + статусбар |
| Чтение | `body.reader` | Только текст (телефон) |
| Только чтение | `body.ro` (книга от другого автора) | Панели скрыты, правка запрещена (`isReadOnly()`) |  
| Фокус (zen) | `toggleZen()` (`15-editor.js`) | Скрыты сайдбар/топбар/статус, `zenAnchor` помнит, что было |

**Данные.** `state` (глобальный объект) → `persist()` (`04-state-seed.js`) пишет в `localStorage` под ключом `LS='chernovik.v2'`. `load()` читает, `seed()` — первый запуск с демо-книгой, `initState()` связывает всё вместе. Сохранение не на каждое нажатие: `scheduleSave()` ставит таймер, `commitNow()` пишет сразу (перед уходом со страницы), `syncCurrentChapter()` перед закрытием главы переносит HTML из редактора в `ch.html`.

**Текст глав.** Главы не разбираются через DOM: `htmlText(html,nl)` (`01-core.js`) вырезает комментарии и теги и декодирует сущности (`HTML_ENT` + `&#…;`) — результат байт-в-байт совпадает с `textContent`; `chText(ch,nl)` (`04-state-seed.js`) оборачивает это кэшем по строке `ch.html` (правка сбрасывает только свою главу; `_txt`/`_txtNl` + `*_Src` — non-enumerable, в JSON/синк не попадают). Вариант `nl` заменяет закрывающие блоки (`</p>`, `</h1-6>`, `</div>`, `</li>`, `</blockquote>`) на `\n` — единица абзаца для связей. На `chText` стоят `chapterTitle`/`chapterWords`, `isPamatka` (регулярка по `<h1>` с DOM-фолбэком только для битых заголовков), связи (`buildCoOccurrence`), `nameStats`/`findContexts`, `wikiPlainAll`, поиск, метки, снапшоты. Тяжёлая обработка главы (санитайзер, `ensureNoteIds`, `applyMarks` — подсветки энц) — только в `loadChapter`, т.е. при входе в главу. Прогон — `dbg-fast`: 80 сравнений паритета + счётчик `tmp()=0` для рендера/связей/энц. Раунд I: полный текст главы материализуется только для открытой главы и панелей по кнопке (поиск/связи/заметки); счётчики слов и цитаты для полки, ленты и сетки «Главы и их начало» считаются `chapterWordsBg` — без создания `_txt` — и дозаполняются фоновыми порциями `bgJob` (прогон — `dbg-bgfill`).

| Служебные ключи localStorage | Файл |
|---|---|
| `chernovik.v2` — книги, настройки | `01-core.js` `LS` |
| `chernovik.thesaurus.v5` — кэш синонимов | `THESAURUS_LS` |
| `chernovik.snapshots.v1` — история версий | `SNAP_LS` |
| `chernovik.accounts.v1` — профили | `ACC_LS` |

Что», «(Вот» — нет, как и в начале фразы), порог 3+ упоминаний **после слияния падежей**, стоп-список `WIKI_STOP` (месяцы, дни недели, «Глава/Часть», порядковые, «Север/Юг», общеупотребительные Что/Как/Вот/Так/Ведь…), уже известные имена/алиасы не дублируются; отчество в любом падеже — `wikiIsPatr()` (Иванович/Ивановичу/Ивановичем, Ивановна/Ивановну/Ивановне) — склеивает имя в полное: «Иван Петрович» = **один персонаж** с алиасами «Иван» и «Петрович», в имени берётся именительный вид отчества; падежные формы одного имени — `sameNameKey()` («маша»/«машу», «марья»/«марье», Иван/Ивана) сходятся в одну запись, выбирается именительный падеж (`nomScore()`), проигравшая форма живёт алиасом (выделение и счётчики работают по всем формам); города/страны и названия отсеяны: стоп-список реальных мест `WIKI_PLACES` по основе слова («Оренбурге» → «Оренбург»), сосед-маркер места `WIKI_PLACE_CTX` («г. Казань», «остров», «улица», «замок»…), предлог-маркер `WIKI_PREP` («в Казани», «из Одессы»), окончания не-имён (-ция, -ство, -ский, -град…); добавляет как `type:'person'` с пустым `desc` — **без описания** (его потом собирает модалка статьи «Собрать описание из текста»); повторный клик дублей не создаёт (тост «Новых персонажей не нашлось»), до 25 имён за раз по убыванию частоты; `wikiMergeDupes()` перед добавлением сливает накопленные дубликаты вики — записи с падежными формами друг друга («Марья Ивановна» и «Марьей Ивановной», «Василиса Егоровна» и «Василисы Егоровны», одно имя дважды) становятся одной, побеждает более упоминаемый, имя и алиасы проигравшего уходят в алиасы победителя; кандидат, совпавший с падежной формой известной статьи (`knownForm`), не добавляется отдельной строкой; сравнение имён с `trim()` — двойник «Марья Ивановна » (с пробелом) тоже ловится; `wikiMergeAuto()` молча (без тоста) схлопывает дубли при открытии вкладок «Энциклопедия»/«Карта связей» (`setPanelTab` в `10-wiki-panel.js`); кнопка видна только во вкладке «Мир» (вместе с «+ статья») |

**Сбор данных по книге** (`09-cooccurrence.js`):
`buildCoOccurrence(force)` — сквозной проход по главам, кэш `coCache` (сбрасывается `invalidateCo()`); вес пары — +2 в одном предложении, +1 в одном абзаце (пара, уже учтённая в предложении, не дублируется — флаг `inSen`), текст главы — `chText(ch,true)` (блоки → `\n`, без DOM, кэш по главе), порог фрагмента 4 знака. Слева направо: `08-declensions.js` даёт формы имени (`declForms`, `buildNameRegexAll` — падежи/числа через `LEMMA_RULES`; в `buildNameAltsAll` каждый вид дублируется парой ё/е, а твёрдое окончание порождает и «-ым» — «Гринёв»/«Гринев», «Гринёвым»/«Гриневым» — это одна персона; готовые формы мемоизируются — `NAME_ALTS_MEM` по списку имён, пересчёт только при первом вызове, кэш сбрасывается после 600 ключей), `findContexts()` ищет вхождения, `nameStats()` считает. Результат — «где встречается» (таймлайн `timelineHtml()`) и связи (`relationsOf()`).

## 18. Импорт книги (`24-import.js`)

Карточка «Импорт книги» на полке (кнопка `impShelfCard` в `renderLibrary` из `15-editor.js`) открывает скрытое поле `#impInput`; выбранный файл уходит в `impFile` → `impParse` → `impAddBook`, новая книга открывается в редакторе. Всё работает прямо в браузере, без сервера.

| Кусок | Что делает |
|---|---|
| `impKind` | Определяет формат по сигнатуре файла (`%PDF-`, `PK`, `{\rtf`, `BOOKMOBI@60`, `FictionBook`, `<!doctype html`), расширение — только запасной путь |
| `impDec` / `impDecDecl` | Кодировки: BOM, UTF-16-эвристика, строгий UTF-8, иначе cp1251; XML-декларация `encoding=` для FB2 |
| `impTxt`, `impHtml` | Текст и веб-страница: чистка (`impPrep`), блоки (`impBlocks`), заголовки по иерархии h1–h3 (`impDocChapters`), иначе — деление по тексту (`impChaptersParas`); ядро текста — `impCleanText` (переносы строк, BOM, табы, NBSP, невидимые и управляющие символы, `\f` = пустая строка), `impJunk` (мусор страниц: «- 15 -», «15», «15/16», «стр. 15», «page 7», «№ 3», разделители без букв — «***», «---», «...») и `impParas` (текст → абзацы: пустая строка = граница; строки-мусор выпадают ДО разбора и абзац не рвут; блок без пустых строк, где ≥60% строк кончаются предложением, разбирается построчно — «строка = абзац», даже если в файле не было `\n\n`; иначе строки склеиваются — это переносы внутри абзаца, дефис на конце строки («слово-\nтекст») склеивается без пробела; реплика, начинающаяся с тире, начинает новый абзац; стихи/пьесы: много коротких строк без точек — строка = абзац). Мусор и `<br><br>` внутри `<p>` источника вычищаются и в HTML/FB2/RTF-путях (`impBlocksHtml`, `impParasHtml`, `impFb2Paras`, `impRtf`) |
| `impFb2` | FB2: `section`/`title`/`p`/`subtitle`/`cite`/`epigraph`/`empty-line`, автор и название из `binary-title-info` |
| `impZip`, `impEpub` | EPUB: каталог ZIP вручную (EOCD + central directory), распаковка через `DecompressionStream('deflate-raw')`, `container.xml` → OPF, главы из spine, оглавление из nav.xhtml/NCX, метаданные `dc:title`/`dc:creator` |
